1. The this Keyword (Easy Explanation)Real-Life AnalogyThink of this as the word "ME" or "MYSELF".When you say, "My name is Ravi", the word "my" refers to you, not anyone else in the room. In Java, inside any object, this literally means "this exact object right here".There are 3 simple situations where you need this.Situation 1: "My Variable vs Parameter" (this.variable)When a constructor/method parameter has the exact same name as your class variable, Java gets confused (called variable shadowing).Plain variable name (age) $\rightarrow$ refers to the local input argument.this.age $\rightarrow$ refers to the object's own field.Code ExampleJavaclass Student {
    String name; // object's field
    int age;     // object's field

    // Constructor with matching parameter names
    Student(String name, int age) {
        // Without 'this', Java assigns local parameter to itself (name = name does nothing!)
        this.name = name; // "Put input 'name' into MY 'name'"
        this.age = age;   // "Put input 'age' into MY 'age'"
    }

    void display() {
        System.out.println("Name: " + this.name + ", Age: " + this.age);
    }
}

public class ThisVariableDemo {
    public static void main(String[] args) {
        Student s1 = new Student("Aarav", 20);
        s1.display();
    }
}
OutputPlaintextName: Aarav, Age: 20
Situation 2: Calling Another Constructor of the SAME Class (this())If your class has multiple constructors, you don't need to rewrite the same assignment code over and over. You can let one constructor call another using this(...).Golden Rule: Just like super(), this(...) must be the very first line inside the constructor.Code ExampleJavaclass Laptop {
    String brand;
    int ram;
    double price;

    // Constructor 1: If user gives only brand
    Laptop(String brand) {
        // Call Constructor 2 with sensible defaults: 8GB RAM, ₹40000 price
        this(brand, 8, 40000.0); // MUST BE LINE 1
        System.out.println("Default config applied for " + brand);
    }

    // Constructor 2: If user gives all 3 values
    Laptop(String brand, int ram, double price) {
        this.brand = brand;
        this.ram = ram;
        this.price = price;
    }

    void showSpecs() {
        System.out.println(brand + " | " + ram + "GB RAM | ₹" + price);
    }
}

public class ThisConstructorDemo {
    public static void main(String[] args) {
        // Uses Constructor 1 (which internally calls Constructor 2)
        Laptop basicLaptop = new Laptop("Dell");
        basicLaptop.showSpecs();

        System.out.println("-----------------------------------");

        // Uses Constructor 2 directly
        Laptop customLaptop = new Laptop("Apple", 16, 120000.0);
        customLaptop.showSpecs();
    }
}
OutputPlaintextDefault config applied for Dell
Dell | 8GB RAM | ₹40000.0
-----------------------------------
Apple | 16GB RAM | ₹120000.0
Situation 3: Passing "Myself" to Another Method or Returning "Myself"Sometimes an object needs to say: "Here is my full identity, inspect me."Javaclass Order {
    int orderId = 501;

    void printReceipt() {
        // 'this' passes the current Order object to a helper service
        ReceiptPrinter.print(this);
    }
}

class ReceiptPrinter {
    static void print(Order o) {
        System.out.println("Generating receipt for Order ID: " + o.orderId);
    }
}

public class PassThisDemo {
    public static void main(String[] args) {
        Order ord = new Order();
        ord.printReceipt();
    }
}
OutputPlaintextGenerating receipt for Order ID: 501
30-Second Summary of thisPlaintextthis.variable   -> "My variable, NOT the parameter with the same name."
this()          -> "Call another constructor inside MY own class."
this            -> "Pass or return ME as a whole object."
2. Method Overriding (Easy Explanation)Real-Life AnalogyThink of an inherited property or family recipe:Your grandfather made coffee using a traditional cloth filter. You inherit his technique (makeCoffee()), but you now own an espresso machine. You keep the exact same name (makeCoffee()), but you replace the outdated recipe with your modern one.In Java:The Parent gives a default method.The Child says: "Thanks, but I want to do this my way."The Child writes the method using the exact same name and inputs, completely overriding the parent's logic.The Big Magic: Dynamic Method Dispatch (Runtime Decision)The most important interview question about overriding: Which method runs?JavaParent obj = new Child();
obj.show();
Type of reference variable (Parent obj): Checked by compiler at compile-time.Actual object in heap memory (new Child()): Determines which version runs at runtime.Because the actual object created is Child, the Child's version ALWAYS wins.Code ExampleJava// Parent Class
class PaymentApp {
    void processPayment(double amount) {
        System.out.println("Processing basic cash/card payment of ₹" + amount);
    }
}

// Child Class 1
class GooglePay extends PaymentApp {
    @Override // Safety check: tells compiler "Ensure I am properly overriding!"
    void processPayment(double amount) {
        System.out.println("Processing ₹" + amount + " instantly via UPI QR Code.");
    }
}

// Child Class 2
class CreditCardPay extends PaymentApp {
    @Override
    void processPayment(double amount) {
        System.out.println("Charging ₹" + amount + " with 2% cashback reward points.");
    }
}

public class OverridingDemo {
    public static void main(String[] args) {
        // 1. Standard parent calling its own version
        PaymentApp baseApp = new PaymentApp();
        baseApp.processPayment(500.0);

        System.out.println("-----------------------------------");

        // 2. Parent reference pointing to GooglePay object
        PaymentApp app1 = new GooglePay();
        app1.processPayment(1200.0); // Runs GooglePay's version!

        // 3. Parent reference pointing to CreditCardPay object
        PaymentApp app2 = new CreditCardPay();
        app2.processPayment(4500.0); // Runs CreditCardPay's version!
    }
}
OutputPlaintextProcessing basic cash/card payment of ₹500.0
-----------------------------------
Processing ₹1200.0 instantly via UPI QR Code.
Charging ₹4500.0 with 2% cashback reward points.
The 3 Must-Know Rules of Overriding+-------------------------------------------------------------------------+
| 1. Signature must be IDENTICAL : Same method name, same parameter types. |
| 2. Visibility CANNOT shrink    : If Parent is public, Child CANNOT be   |
|                                  default or private.                    |
| 3. What CANNOT be overridden?  : 'private', 'final', and 'static'.      |
+-------------------------------------------------------------------------+
Why can't private methods be overridden?
Because the child class can't even see them, let alone override them.Why can't final methods be overridden?final literally means: "This is the final version, no subclass is allowed to change it."Why can't static methods be overridden?static belongs to the Class at compile time, not to an Object at runtime. If a child re-declares the same static method, it is called Method Hiding, not overriding.30-Second Summary of Method OverridingPlaintextWhat is it?     -> Child re-writes a Parent's method with the exact same name & parameters.
Why use it?     -> To give custom behavior while keeping the method name standard.
Which one runs? -> The one belonging to the actual object created with 'new' in the heap.

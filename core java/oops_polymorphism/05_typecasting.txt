2. Downcasting (Parent $\rightarrow$ Child)What is it?Converting a superclass reference back to a subclass type.JavaParent p = new Child();  // First upcast
Child c = (Child) p;     // Explicit downcast
Explicit: Requires (Subclass) cast syntax.Risk: If the reference does not actually hold an instance of that subclass at runtime, the JVM throws a ClassCastException.Visualizing the Problem: ClassCastExceptionValid Downcast:
[new Dog()] ---> Upcast to Animal ---> Downcast back to (Dog) ---> SUCCESS!

Invalid Downcast:
[new Cat()] ---> Upcast to Animal ---> Downcast to (Dog) --------> ClassCastException!
To avoid this crash, always verify using the instanceof operator before downcasting.Complete Code Example: Upcasting, Downcasting & instanceofJava// Parent Class
class Animal {
    void eat() {
        System.out.println("This animal eats food.");
    }
}

// Subclass 1
class Dog extends Animal {
    @Override
    void eat() {
        System.out.println("Dog eats meat and bones.");
    }

    void bark() {
        System.out.println("Dog barks: Woof woof!");
    }
}

// Subclass 2
class Cat extends Animal {
    @Override
    void eat() {
        System.out.println("Cat drinks milk.");
    }

    void meow() {
        System.out.println("Cat meows: Meow meow!");
    }
}

public class TypeCastingDemo {
    public static void main(String[] args) {
        // ==========================================
        // 1. UPCASTING (Implicit & Safe)
        // ==========================================
        Animal a = new Dog(); // Child -> Parent
        a.eat(); // Executes Dog's overridden eat() via Dynamic Method Dispatch

        // a.bark(); // COMPILER ERROR: 'bark()' does not exist in class Animal!

        System.out.println("-----------------------------------");

        // ==========================================
        // 2. DOWNCASTING (Explicit)
        // ==========================================
        // We know 'a' holds a Dog, so we cast it back to Dog to call bark()
        Dog d = (Dog) a;
        d.bark(); // Now accessible!

        System.out.println("-----------------------------------");

        // ==========================================
        // 3. SAFE DOWNCASTING WITH 'instanceof'
        // ==========================================
        Animal unknownAnimal = new Cat();

        makeAnimalSound(unknownAnimal);
        makeAnimalSound(a); // passing Dog
    }

    // Helper method handling polymorphic objects safely
    static void makeAnimalSound(Animal animal) {
        if (animal instanceof Dog) {
            Dog d = (Dog) animal; // Safe Downcast
            d.bark();
        } else if (animal instanceof Cat) {
            Cat c = (Cat) animal; // Safe Downcast
            c.meow();
        } else {
            animal.eat();
        }
    }
}

30-Second Quick RevisionPlaintextObject Class:
  - Root of ALL classes in Java (java.lang.Object).
  - toString() : Override to print clean object details.
  - equals()   : Override to compare values instead of memory references.

Upcasting:
  - Parent p = new Child();
  - Implicit (automatic). Safe.
  - Restricts access to parent-declared methods only.

Downcasting:
  - Child c = (Child) p;
  - Explicit cast syntax required.
  - Dangerous: Throws ClassCastException if the heap object isn't actually that Child type.
  - Always guard with: if (p instanceof Child) { ... }

  1. The Object Class (The "Grandfather" of All Classes)
Real-Life Analogy
Imagine a huge family tree. No matter whether you are an engineer, a doctor, or a student, everyone at the very top shares the same Great-Grandfather.

In Java, Object is that Great-Grandfather.
Even when you create a brand-new class from scratch, Java secretly connects it to Object behind the scenes.

Java
// You write this:
class Mobile { }

// Java quietly turns it into this:
class Mobile extends Object { }
Because Mobile is a child of Object, your Mobile class gets a few free built-in tools from Object. The two most important ones are toString() and equals().

Tool 1: toString() (How an object introduces itself)
By default, if you try to System.out.println(myPhone), Java prints ugly memory garbage like Mobile@4517d9a3.
Overriding toString() simply teaches your object how to introduce itself in clean English.

Java
class Mobile {
    String brand;
    int price;

    Mobile(String brand, int price) {
        this.brand = brand;
        this.price = price;
    }

    // Teaching Java how to print this object cleanly
    @Override
    public String toString() {
        return brand + " costs ₹" + price;
    }
}

public class ObjectDemo1 {
    public static void main(String[] args) {
        Mobile m = new Mobile("Samsung", 25000);
        
        // Automatically calls toString()!
        System.out.println(m); 
    }
}
Output:

Plaintext
Samsung costs ₹25000
Tool 2: equals() (Checking if two things are the same)
Suppose you and your friend both buy the exact same Samsung phone for ₹25,000.

If you use ==, Java checks: "Are these the exact same physical phone in one hand?" 
→ False (There are 2 separate phones!).

If you override equals(), you tell Java: "Check if the brand and price inside them match." 
→ True!

2. Object Type Casting (Wearing Different Hats)
To understand Object Casting, think of a Smartphone (Child) and a Basic Phone (Parent).

Every Smartphone IS A Phone (it can make calls).

Not every Phone is a Smartphone (a basic Nokia cannot take selfies).

There are two ways to look at this object: Upcasting and Downcasting.

1. Upcasting (Child 
→ Parent) = "Zooming Out"
You take a Smartphone (Child), and put it in a box labeled "Phone" (Parent).

Java
Phone p = new SmartPhone(); // Upcasting (Automatic!)
What happens? Java allows this automatically without any complaint because a Smartphone is a Phone.

The Catch: Because the label on the box says Phone, Java only lets you press Phone buttons (makeCall()). Even though a Smartphone is inside the box, Java hides the takeSelfie() button!

2. Downcasting (Parent 
→ Child) = "Opening the Box"
Now you want to take a selfie! You have to tell Java: "Hey, trust me, what's inside that Phone box is actually a SmartPhone. Unbox it!"

Java
SmartPhone sp = (SmartPhone) p; // Downcasting (Manual!)
sp.takeSelfie();                // Now the selfie button works!
The Danger (ClassCastException): What if a basic NokiaPhone was inside that Phone box, and you lied to Java saying "Unbox it as a SmartPhone"? The program will crash!

Complete Easy Example with Output
Java
// Parent Class
class Phone {
    void makeCall() {
        System.out.println("Calling a friend...");
    }
}

// Child Class
class SmartPhone extends Phone {
    void takeSelfie() {
        System.out.println("Click! Taking a selfie...");
    }
}

public class CastingEasyDemo {
    public static void main(String[] args) {
        
        // 1. UPCASTING: Putting SmartPhone inside a Phone label
        Phone myDevice = new SmartPhone(); 
        
        myDevice.makeCall();     // WORKS! Because all Phones can make calls.
        // myDevice.takeSelfie(); // ERROR! Java thinks it's just a normal Phone right now.

        System.out.println("-------------------------");

        // 2. DOWNCASTING: Telling Java "Treat myDevice as a SmartPhone again!"
        if (myDevice instanceof SmartPhone) { // Safety check before opening box!
            SmartPhone mySmartPhone = (SmartPhone) myDevice;
            
            mySmartPhone.makeCall();   // WORKS!
            mySmartPhone.takeSelfie(); // WORKS NOW!
        }
    }
}

Plaintext
OBJECT CLASS:
  - Every class secretly extends 'Object'.
  - Override toString() -> so System.out.println(obj) prints text instead of @12ab34.
  - Override equals()   -> to compare data inside two objects instead of memory addresses.

UPCASTING (Child -> Parent):
  Phone p = new SmartPhone();
  - Happens automatically.
  - You lose access to Child-only methods (can only use Parent methods).

DOWNCASTING (Parent -> Child):
  SmartPhone sp = (SmartPhone) p;
  - Must write (ChildClass) manually.
  - Unlocks Child-only methods again.
  - Always check with 'if (p instanceof SmartPhone)' so the program doesn't crash!
